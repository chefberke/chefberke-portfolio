In a small team, the hard part is rarely the code. It is knowing what the others
know. At the end of September, we started writing it down. Here are the pull
requests we merged each month.

```note
aug  █ 18 (one week)
sep  ██████████████ 287
oct  ████████████████████████████ 585
nov  ██████████████████████░░░░ 455 so far, around 550 by month end
```

About 28 pull requests a week at the beginning. About 135 since October, almost five
times as many. Same team, actually one person fewer. And they did not get
smaller: a typical one went from about 110 changed lines to about 150.

## What changed

We write things down now, for each other and for the AI we work with. A design
system, so every new screen is built from the same pieces. Decisions, each one with
the reason behind it. Skills, short guides the AI reads, so a problem we solve once
stays solved.

None of it is impressive on its own. But together it means nobody starts from zero.
Not us, and not the AI. It already knows the product, so we spend our time on what
to build instead of explaining where we are.

The biggest change for me was not speed. It was not having to ask. I open a task
and everything I need is already there.

## The point

You do not need a bigger team to move faster. You need a team that shares what it
knows, and tools that can read it. Write it down once. Let everyone, human or not,
start from there.
